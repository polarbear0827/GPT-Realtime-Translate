# Changelog

## v0.6.2 - 2026-10-13

- Connecting the app to the sharing relay is automatic: after `npm run relay:deploy` the app asks
  "連接分享伺服器？" and one click connects it — no copying the URL or publish key. The script opens the
  app with a `keynote-live-translator://share-setup` link; the app always asks before connecting, and
  rejects links without https or a valid key. `npm run relay:connect` reconnects without deploying.
- The share panel's setup now shows the two steps, with manual entry tucked away.

## v0.6.1 - 2026-10-13

- Sharing adapts its update rate to the audience size (4 updates per second up to 400 viewers, 2 up to
  1,500, then 1). Measured on Cloudflare: with 1,000 viewers every update now arrives within the
  network round trip (95% within 0.35 s), where 4 updates per second had queued up to several seconds.
- `npm run relay:deploy` no longer stops to ask about updating Wrangler's AI-agent "skills".
- Load test: the host's update rate follows the app by default (`--rate auto`); `--pad` adds text to
  each update to tell bandwidth limits from message-count limits.
- CI: the relay tests stop wrangler cleanly on Linux.

## v0.6.0 - 2026-10-13

### Share the translation with the audience
- **分享** panel: start a share and the audience scans a QR code to read the captions live on their own
  phones — no app, view only, works on mobile data. The QR code can be projected full screen (Q, also
  on the caption window) or shown small in the corner of the captions.
- Viewer page: large readable captions with the newest sentence highlighted, optional original text
  (if the speaker allows it), text size, dark/light, keeps the screen awake, reconnects and catches up
  automatically, late joiners get the recent sentences.
- Speaker controls: live viewer count, pause (nothing said while paused is ever sent), announcements
  pushed to every phone, end the share. Quitting the app doesn't end the share; reopening offers to
  continue the same room so nobody has to rescan.
- Runs on a relay you own: a Cloudflare Worker with one Durable Object per room (`relay/`), deployed
  with `npm run relay:deploy`. The free plan is enough for typical events. Only the app (with the
  publish key) can create rooms; viewers can't send anything; the page may only connect to your relay.
- Load-tested locally with 2,000 simulated viewers: all updates delivered, p95 latency 65 ms
  (`npm run relay:load-test`).

### Other
- QR codes are generated by a small built-in encoder (verified with Apple's Vision in the tests).
- The translation is shared whether or not the transcript is being recorded.

## v0.5.2 - 2026-10-13

Floating captions are now responsive and adjustable:
- Resize from any edge or the corner grip; the text size follows the window height and the line width
  follows the window width. A− / A+ resize the window in steps.
- Background opacity from solid frosted glass to fully transparent (hover slider or Settings); the text
  shadow strengthens automatically as the background fades, so captions stay readable over video.
- Settings > 懸浮字幕: opacity, 1–3 translation lines, show/hide the original, lock (click-through),
  reset position and size.

## v0.5.1 - 2026-10-13

- Fixed "翻譯連線逾時" when translating system audio: the app now streams the captured audio to
  gpt-realtime-translate over its own WebSocket (authenticated with your key) instead of WebRTC, so
  it works on any network where the transcription connection works.
- Microphone mode (WebRTC): the connection timeout no longer includes the time OpenAI takes to answer,
  an open event channel counts as connected, and a timeout now reports the WebRTC state.
- The macOS app's page can be inspected with Safari's Web Inspector for troubleshooting.

## v0.5.0 - 2026-10-12

### Translate what your Mac is playing
- New audio source "電腦播放的聲音": captures YouTube, meetings or any app digitally with a Core Audio
  process tap (macOS 14.2+), so nothing has to play through the speakers; works with headphones.
  Optional "mute the original" while translating. Warns when no audio arrives (usually permission).
- Floating captions window (懸浮字幕): frosted glass, always on top, visible over full-screen video, never
  takes focus. Large translation with the original in a smaller line below; whole recent sentences are
  fitted to two lines. Hover for size / lock (click-through) / close; ⌘⇧O and ⌘⇧L in the View menu.
  Opens automatically when starting with system audio.

### Appearance
- Light mode, plus "follow system" (the default); the macOS window chrome follows the choice.
- Caption background (black / chroma-key green) now applies to the caption panes in every view, so the
  effect is visible while setting up, and full-bleed in presentation mode and the caption window.

### Reliability
- Fixed a flaky test that could hang CI; CI jobs and tests have timeouts.
- The main page keeps running while hidden behind full-screen video (unthrottled scheduling on macOS 14+).

## v0.4.0 - 2026-10-12

### Models
- Source captions now use `gpt-live-transcribe` (replaces `gpt-realtime-whisper`), with `languages`,
  optional keywords and context prompt. Translation stays on `gpt-realtime-translate`.
- Speech turns are committed by a client-side voice activity detector instead of every 900 ms.
- Option to take bilingual source text from the translation session (about half the audio cost).

### Fixes
- macOS: Export, Clear Transcript and Fullscreen now work; ⌘C/⌘V/⌘Q work (app now has a main menu).
- Transcript entries no longer repeat earlier segments; repeated characters (謝謝, 100%) are kept.
- Chinese conversion no longer changes 公里/皇后/划船…, and phrases split across deltas convert correctly.
- SRT cues are at most 7 s / 2 lines in every mode, bilingual cues stay aligned, no empty cues.
- Start no longer wipes the previous transcript; the timeline continues.
- Errors no longer leave connections running with Stop disabled; Stop during startup cancels it.
- Microphone selection is kept (and remembered) after testing or starting.
- Layout no longer breaks at the default window size; panels no longer overlap the toolbar.

### Security
- Dev server checks Host, Origin, Content-Type and a per-launch token (DNS rebinding / CSRF).
- macOS: Node.js removed; the native app serves static files only and handles the API key over a
  WKWebView bridge.
- Microphone permission and navigation are limited to the app's own page.
- Optional "remember key" in the macOS Keychain.

### Reliability & performance
- Automatic reconnect, rotation before the 60-minute session limit, graceful stop that keeps the last sentence.
- Audio processing moved to an AudioWorklet with an anti-aliased 24 kHz resampler.
- Transcript panel renders incrementally; captions render once per frame.
- Keeps the display awake while live; warns after 20 s without audio; auto-backup of the transcript.

### UI
- Consistent Traditional Chinese UI, single Start/Stop button, connection status, level meter, timer.
- Settings and transcript drawers, export menu, presentation mode, caption window for a second screen,
  keyboard shortcuts, 13 languages, configurable mic processing and noise reduction.

### Engineering
- Frontend split into ES modules; shared `realtime-config.json` for all backends.
- Tests: unit, server security, session controller, Swift↔Node contract, offscreen WKWebView bridge test.
- Version read from `VERSION` everywhere; universal macOS build (~2 MB, was 115 MB); non-relocatable pkg;
  optional Developer ID signing/notarization in CI; Node 24 in CI.

### Removed
- The Android app, its build script and CI jobs. Releases ship the macOS installer only.
